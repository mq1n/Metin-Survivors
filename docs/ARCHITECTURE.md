## 2. Toolchain

- bun ≥1.3 workspaces; TypeScript `strict`, `noUncheckedIndexedAccess`; ESM only.
- Client: Vite, `three` (latest, WebGLRenderer / WebGL2 only), Preact + `@preact/signals` (UI), vitest.
- Worker: Hono, D1, R2, Durable Objects (WebSocket hibernation), vitest + `@cloudflare/vitest-pool-workers`.
- Assets: `@gltf-transform/core|extensions|functions` + `meshoptimizer` (no gltfpack); WebP textures; MP3 audio (universal decode).
- Commands (root): `bun run dev` (Vite), `bun run build`, `bun run test`, `bun run typecheck`, `bun run deploy` (`scripts/deploy.ts`: clean-room audit → manifest → typecheck → tests → `MS_STRICT_ASSETS=1` build without source maps → site contract + dist audit → local Worker/Function bundles → D1 migrations → Worker → Pages → smoke test; `deploy:check` = the local gates only, `deploy -- --dry-run` prints every step and touches nothing remote; README.md → Deploy).

## 3. Conventions

- Units: **1 unit = 1 m**. Y up. Ground plane XZ. Character forward **+Z**. Angles radians; `rot` = yaw around +Y, 0 → facing +Z.
- Sim is 2D on XZ (`x`, `z`); height comes from `TerrainField.heightAt(x,z)` (render, projectiles that need it).
- Fixed sim step `DT = 1/60`; render interpolates `prev → cur` with alpha. Sim never reads wall-clock or `Math.random` — use `Rng` (seeded, `sim/rng.ts`), so co-op host and replays are deterministic.
- Time in seconds (float) inside sim; run clock `runTime` starts at 0, run length 900 s (15:00).
- Colors: hex strings `#rrggbb` in data; linear floats inside render.
- Asset ids: lowercase `snake_case`, unique per kind (`wolf`, `alpha_wolf`, `warrior_m_t2`, `metin_sorrow`, `tex_grass_a`, `icon_skill_sword_spin`, `sfx_hit_flesh_01`, `mus_yongan_combat`).
- Localized content text: inline `{ tr, en }` (`L10n`). UI chrome text: `i18n/*.json` keys. Default language = browser language (`tr*` → tr, else en).

## 4. Content (`apps/game/src/data/schema.ts`)

`schema.ts` is the typed contract for all game data (classes, skills, passives, spirit stones, trinkets, enemies, bosses, metins, zones/time bands, gear, talents, empires, story, balance). Content files: `apps/game/src/data/content/<collection>.json`, loaded and validated at startup by `data/loader.ts` (and in a vitest). Every cross-reference (enemy id in a band, icon id, model id, sfx/vfx preset) must resolve; validation fails the test suite otherwise — this is how missing assets are caught before ship.

## 5. Asset manifest and producer contracts

Manifest parts (each owned by its producer), merged by `tools/pipeline/manifest.ts` into `public/assets/manifest.json` (types in `apps/game/src/data/assetManifest.ts`):

| Part file (`public/assets/manifest/`) | Producer |
|---|---|
| `models.json` | FORGE |
| `textures.json` (terrain, foliage, vfx, portraits, illustrations) | IMAGEGEN (+ FORGE for baked textures) |
| `icons.json` | IMAGEGEN |
| `audio.json` | AUDIO |

Content hashes in file names (`wolf.3f9a1c.glb`) → served `immutable`; the manifest itself is `no-cache` (`apps/game/public/_headers`; `bun run deploy` refuses a build with an unhashed file under `/assets` other than the manifests).

### 5.1 GLB contract (FORGE output)

- One `.glb` per model id at `public/assets/models/<kind>/<id>.<hash>.glb`; `kind ∈ creature|boss|hero|weapon|metin|prop|tree|pickup`.
- Meters, Y-up, faces +Z, origin on the ground at the footprint centre. Rest pose = neutral stance.
- Creatures/bosses/heroes: exactly **one skinned mesh, one material** (heroes may have ≤3 meshes: body, hair, armor tier merged where possible); attributes `POSITION, NORMAL, COLOR_0` (+ optional `TEXCOORD_0` with `baseColorTexture`), `JOINTS_0/WEIGHTS_0` ≤4 influences normalized. Root joint `root`. Socket bones named `head`, `hand_r`, `hand_l`, `back`, `muzzle` (mouth/breath origin), `chest` where they exist.
- Clips (lowercase): `idle`, `walk`, `run`, `attack`, `attack2`, `hit`, `death`, `spawn`, `special1..3`; heroes add `cast`, `dash`, `victory`; metins: `drop`, `idle`, `pulse`, `shatter`. Loops: idle/walk/run/pulse. Locomotion clips are in-place (no root motion).
- Scene `extras`: `{ id, kind, height, radius, hit: { attack: <sec>, attack2: <sec>, ... }, sockets: { hand_r: "<bone>", ... }, palette?: string[], breath?: { start, end }, flyHeight?: number }`. `breath` = seconds into `special1` during which the model breathes fire: such a boss plays its breath pattern on `special1` (other patterns on `special2`/`special3`), surges its emissive in that window and its breath VFX leave the `muzzle` socket. A boss's arrival (invulnerable intro) lasts its `spawn` clip, 1.6–4 s.
- Budgets: crowd creatures 1.5k–5k tris, ≤32 joints; bosses ≤15k tris, ≤48 joints; heroes ≤12k tris; weapons ≤1.5k; props ≤3k (instanced ones ≤800); landmarks drawn once (`LANDMARK_IDS`, e.g. `prop_giant_pagoda`): ≤8k tris, 2048 albedo. meshopt-compressed + quantized.
- Forbidden: visible primitive construction (raw cones/cylinders/spheres/boxes read as such), untextured flat-shaded blobs, z-fighting shells, exploded skinning.

### 5.2 Textures/icons (IMAGEGEN output)

- `public/assets/textures/<group>/<id>.<hash>.webp` (terrain albedo 1024² tileable + derived normal `_n`; foliage cards RGBA; vfx sprites RGBA), `public/assets/icons/<id>.<hash>.webp` (128² painted, consistent style, rarity frame applied in CSS), `public/assets/ui/*` (panel/frame textures, logo, portraits, zone cards, splash).
- Raw generations + prompts are kept in `.research/imagegen/` (prompt, seed info, raw PNG) for reproducibility; only post-processed outputs ship.

### 5.3 Audio (AUDIO output)

`public/assets/audio/{sfx,music}/<id>.<hash>.mp3`; manifest entry `{ id, url, kind, duration, loop, gain, variants? }`. Loudness: SFX peak ≤ -1 dBFS, music ≈ -16 LUFS integrated, loops seamless.

## 6. Simulation (`apps/game/src/sim`)

- `World` owns all state; `world.step(inputs)` advances one fixed tick and appends to `world.events` (cleared at the start of each tick; consumers must not retain event objects).
- SoA stores (typed arrays, capacity-preallocated, swap-remove with stable ids via generation): `EnemyStore` (x, z, px, pz, vx, vz, rot, type, hp, hpMax, radius, speed, state, stateT, animClip, animT, flash, status bits, eliteTier, corrupted, scale), `ProjectileStore`, `PickupStore` (xp gems merge beyond cap), `ZoneStore` (ground AoEs), `TelegraphStore`. Players: small array of `PlayerState` (co-op ready, index 0 = local in single player).
- Spatial hash (cell 4 m) rebuilt per tick for enemies; queries by circle/cone/segment.
- Skills: data-driven behaviors (`sim/skills/behaviors/*.ts`), one module per `BehaviorKind` (see schema). Behavior instances read final params = rank params × upgrades × player stats.
- Events (`sim/events.ts`): typed union `SimEvent` — damage, enemyDeath, enemySpawn, playerHit, playerDeath, levelUp, pickup, skillCast, vfx (generic VFX request: preset + position/direction/scale/duration/color), sfx, telegraph, metinWarn/metinImpact/metinAwaken/metinBreak, bossSpawn/bossPhase/bossDeath, chestOpen, story, runEnd.
- Run lifecycle: `RunConfig { zone, difficulty, classId, doctrine, sex, empire, seed, meta: MetaBonuses }` → `World` → `RunResult` (stats for results screen, leaderboard, talent XP).
- Caps: 600 live enemies (spawner throttles), 1500 projectiles, 1200 pickups.

## 7. Render (`apps/game/src/render`)

- `WebGLRenderer` (antialias off when DPR>1.5), ACES tone mapping, sRGB output, exponential fog per zone, hemisphere + directional sun (shadow only for hero + nearby props; crowd uses instanced blob shadows).
- Camera: perspective FOV ≈40°, pitch ≈55°, distance ≈22 m (zoomable 16–30), smooth follow; shake via events.
- **First-use compile hitches** (`RenderWorld.warmup` → `render/warmupPass.ts`, called at the end of `RunSession.load` and again after the first frames): ANGLE/D3D11 builds a (program × vertex layout) variant at its first draw, so a program that is linked but first drawn in play stalls that frame (tens of ms, a 645 ms outlier measured on a loaded machine). The warm-up therefore shows pooled/hidden meshes, switches frustum culling off for two real frames through the composer, and places the sun's shadow frustum on the hero first (`env.followShadow`), so one of everything is drawn in both the main and the shadow pass; everything it changed is restored in a `finally`. The hero's meshes carry an own `MeshDepthMaterial` each (`HeroView.depthMaterial`, three's default settings): three's single shared depth material changes program from caster to caster, which made the weapon's shadow program depend on what was drawn before it. Measured with the stepped probe (`.research/prod4/runtime-memory-net/step.ts`): no program link and no first use after the loading screen in 571 stepped frames, where the old warm-up left the `bridges` ground program to its first draw (78-91 ms frames at the teleport). What it does not cover: programs of meshes that stream in after the warm-up (props, `?payload=1`), and GPU-process raster tasks of the HUD (16-59 ms on the GPU main thread, they stall WebGL in the first seconds of a run).
- **Crowd**: one `InstancedMesh` per enemy type; clips baked at load into a bone-matrix `DataTexture`; vertex shader skins per instance from `(clip, time)` attributes; per-instance attributes for hit flash, corruption glow, tint, dissolve (death). Target: 600 animated enemies ≤ 2 ms GPU on mid dGPU.
- Hero: `SkinnedMesh` + `AnimationMixer`, weapon attached to socket, armor tier = model swap.
- Damage numbers: single instanced quad batch + glyph atlas (crit = larger, color by element).
- Quality tiers `low|medium|high|ultra` (DPR cap, shadows, post, VFX density, crowd cap) + auto-downgrade on sustained frame time > 20 ms.
- Render reads sim stores directly (read-only). It never mutates sim state.

### 7.1 Terrain & zone scene (`apps/game/src/world`, `render/terrain`, `render/vegetation`)

- **Sim side** (`world/terrainField.ts`): `createTerrainField(biome)` is the only ground truth the sim sees — `walkable`, `moveCircle`, `surfaceAt`, `heightAt`. Zone layouts are recipes in `world/zones/<zone>.ts`; `bun run src/world/debug/dumpLayout.ts <zone>` prints walkable/reachable % (re-run after any recipe change).
- **Field memo and run lifetime** (`createTerrainField`): a baked field is ~6 MB of typed arrays. Fields of the zone's default seed (`seed === biome.seed`: zone atlas, previews, the map worker, tools) sit in a strong LRU of 4. A field of any other seed is a run's own (the run seed is new every run): it is only findable while somebody holds it (a weak memo, so the main-thread map fallback during the run reuses it) and is garbage with the run. What must not keep a finished run alive (heap-snapshot retainer paths, prod4): `DecalGrid` holds the height sampler weakly (the sampler is a closure over the run session), `RunSession.dispose` clears the VFX adapter's `skillMeta` (a closure over the run's skill feed and world) and `renderer.renderLists` (three keeps the last frame's render items, whose terrain material `onBeforeCompile` closure held the field). GPU resources count too: `renderer.info.memory.textures` in the menu must be identical after every run (the liquid's 1 x 1 white `uLight` stand-in, bound until the terrain's light map exists, was never disposed: +1 texture per run in Yongan / Seungryong / Sohan; it is released when the baked map replaces it and by `dispose()`, `render/terrain/liquid/standIn.test.ts`). Probe protocol and numbers: `.research/prod4/runtime-memory-net/NOTES.txt` (`curve.ts`: no in-page hooks, JS heap after two forced GCs + `backingStorageSize` per menu -> run -> quit cycle, WeakRef counts of session / world / field).
- **Seed semantics**: `ctx.seed = biome.seed` for ground + landmarks (identical every run, so landmarks and paint never move); scatter (vegetation, clutter, props off the landmark list) varies with the run seed; the recipe owns the liquid level.
- **Bridge-deck contract**: `grid.heights = max(bed, deck)` is what walkability/`surfaceAt` read. The render mesh, liquid depth, paint and light bake use `grid.bed` / `bedHeightAt` instead, so a bridge never raises the riverbed. Rope bridges need `yMid >= yEnd - 0.1` in the recipe.
- **Render side**: `createZoneScene(core, field, biome)` (`render/terrain/zoneScene.ts`) returns `{ group, ready, systems, update(dt, camera, focus), setQuality, dispose }`; `RunSession.load` pulls it in through `import.meta.glob('../render/terrain/zoneScene.ts')` and adds `group` (`zone:<id>` → sky, terrain, liquid, vegetation, structures) to the scene. Whole scene budget at the gameplay camera on `high`: ≤ 60 draw calls, terrain + vegetation + structures ≤ 1.2 ms GPU.
- **Occlusion hook**: our own materials call `applyOcclusionFade(shader)` (`heroViewUniform`, `occlusionRadius`) so props/trees fade out where they would hide the hero from the camera.
- **Zone look** (`render/terrain/look/<zone>.ts`, type `ZoneLook`): the per-zone art data — layer style/tints, accent hue patches, shadow tint + fill (`fill`, `shadow`), cloud shadows, depth haze + low mist, baked light pools under lanterns/braziers (`pools`), shader decals (`decals`), the ground seal landmark (`seal`), per-layer roughness, lava emissive cap. `lookFor(zone)` resolves it; everything else (`terrainMaterial.ts`, `atmosphere.ts`, `terrainDecals.ts`, `bakeLight.ts`, `bakePools.ts`) is shared code.
- **Zone isolation contract** (zones core C0, `look/types.ts`): every field added for the zone rebuild is optional and its absence reproduces the previous look (`style.calm|cliff|blend`, `shadow.soft`, `liquidLook`, `cover`, `trees`, `occlusion`, `edge`, `rockCaps`, `readability`, `biome`, `targets`; each names the core item that consumes it). `resolveBiome(zoneId, biome)` (`look/index.ts`) merges `look.biome` (fog / sky / sun / ambient / particles / water tint) over the content preset and is applied at every render call site (`RunSession.load`, terrain gallery, lineup demo); the sim and `createTerrainField` keep the content preset, and `data/content/zones.json` is core-only. Sky/backdrop values live per zone in `render/terrain/sky/zones/<zone>.ts`; enemy readability per zone in `look.readability` (falls back to `render/zoneReadability.ts`); rock caps in `look.rockCaps` (falls back to the id-substring `capStyleFor`); the glowing ground layer is `GroundLayer.emissive: true` (falls back to the id `tex_lava_crust`). `world/kit/index.ts` holds the C7 layout-kit signatures (they throw `KitPending` until C7 lands). Gates and regression shots: `tools/qa/zonecheck.ts` with `.research/zones_core/spots.json`.
- **Atmosphere** (`atmosphere.ts`): `applyAtmosphere(shader)` patches only terrain/structure/vegetation materials (never a global `ShaderChunk`, so hero/crowd/VFX are untouched). Uniforms are `uAtmo*`-prefixed to avoid clashing with materials that already declare `uTime`/`uWindDir`.
- **Decals** (`terrainDecals.ts`): pebbles, leaves, scratches, voronoi cracks, specks, streaks, cells and the seal are evaluated in the terrain fragment shader — no geometry, no draw calls. `uDecalCount` bounds the loop (medium = 2, high/ultra = all); the `Q_DECOR` define removes the whole block on `low`.
- **Props**: `PROP_DEFS` (`world/props.ts`) prefer a shipped `prop_<id>` GLB (`manifest.kind === 'prop'`, `assets.hasModel('prop_' + id)` in `render/terrain/structures/index.ts`) and fall back to the procedural builder when it is absent.

## 10. Online (`workers/api`, `packages/shared`)

Base path `/api/v1`. Auth: anonymous `POST /players` → `{ playerId, secret }`; requests send `Authorization: Bearer <playerId>.<secret>`; D1 stores `sha256(secret)`.

| Method & path | Purpose |
|---|---|
| `POST /players` | register anonymous player (+ display name, filtered) |
| `PATCH /players/me` | rename |
| `DELETE /players/me` | erasure on request: R2 save, credentials, runs, board rows, transfer codes, the player's `p:<id>` rate counters → 204 (not erasable per player: the hashed-IP counters, which expire by themselves, and a live co-op room, which closes within 3 h). Order: blob delete (a failure → 503, nothing lost, retry) → one D1 batch → blob delete again (a failure is logged, still 204: the rows are gone and the caller could not retry; the daily orphan sweep finishes it). Client: `ApiClient.deleteAccount()` then forgets the credentials and the offline run queue; Settings → Profile & Cloud → Privacy (notice + confirm + inline error) |
| `POST /runs` | submit run result → `{ rank, best }` (plausibility envelope calibrated on the headless sim incl. Run Options ×3: kills/time, level/time, yang/kill, metins, bosses — over it → 422, outliers and runs past run length + slack → stored but unranked; score recomputed server-side; version allow-list) |
| `GET /leaderboard?zone&difficulty&class&period=all|week&limit` | top N + caller's rank. The body depends on the caller only through `you` / `entries[].you`: a request **without** `Authorization` answers `Cache-Control: public, max-age=30, stale-while-revalidate=60` + `Vary: Authorization`; any request carrying credentials answers `private, no-store` (their rank is fresh right after a run and never reaches a shared cache); errors stay `no-store`. The game client always sends its credentials once registered, so the shared cache serves only anonymous visitors/crawlers. Browsers honour `Vary: Authorization`; Cloudflare's CDN does not (it varies on `Accept-Encoding` only) — Worker responses are not cached at the edge unless a Cache Rule or `caches.default` is added, and if one is, it must bypass requests that carry `Authorization` |
| `GET /save` / `PUT /save` | cloud save blob in R2 (`saves/<playerId>.json`), `If-Match` rev; `GET` answers 204 (no body) while the player has no save yet — a normal first sync, never a 404 console error. `PUT` = D1 compare-and-swap on `save_rev`, then the R2 write, then a re-check that the player row still exists: if `DELETE /players/me` erased the player in between, the blob just written is removed again (and the `p:<id>` counter row `enforce` made) and the answer is 401, never a `rev_conflict` and never an orphan blob. A daily `housekeeping` sweep (`saves.ts` `sweepOrphanSaves`: R2 list of `saves/`, blobs older than 1 h whose player row is gone, ≤ 5000 objects per run) is the safety net for a failed R2 call in either path |
| `POST /transfer` / `POST /transfer/claim` | 8-char code to move a profile between devices |
| `GET /coop/:room` (WebSocket) | Durable Object `CoopRoom` relay (host-authoritative) |
| `GET /health` | status |

Write ordering in the client (`net/api.ts`): the calls that change a player's server state — `PUT /save`, `POST /runs` and `DELETE /players/me` — run on one chain in call order (`ApiClient.serialised`; reads, registration and transfer claims are not on it; a stalled response body releases the chain after 30 s). Credentials are read when a call's turn comes, so an erasure waits for the upload that is on the wire (the Worker sees PUT then DELETE) and a save or run issued behind it finds the credentials gone (local 401 `Not registered yet`, a run is queued for the next identity) instead of going out with the erased secret. The offline queue is re-read from storage after every request of a flush and runs are removed by id, so a flush that overlaps an erasure cannot write the erased queue back or drop runs queued meanwhile; `deleteAccount` only clears the identity it erased. `CloudSync` (`meta/cloud.ts`) drops a pending conflict and the synced revision once the credentials are gone, so "keep the cloud copy" can not bring an erased account's data back and the next identity starts like a first link. Production clients call the API same-origin: the Pages Function `apps/game/functions/api/[[path]].ts` hands `/api/*` (WebSockets included) to the Worker through a service binding (`apps/game/wrangler.toml`); unreachable → structured retryable 503. The client (`net/api.ts`) treats a 2xx whose body is not the Worker's JSON (an HTML SPA fallback when `/api` is misrouted, a proxy page, truncated JSON, a non-object) exactly like being offline — `ApiError` status 0 / code `network`, retryable: runs stay queued, the cloud sync retries, the UI says "can't reach the server" — never a crash or a terminal rejection. `VITE_API_BASE` (build time) overrides the base, e.g. with the workers.dev URL. Rate limits per IP + player (Workers rate-limit bindings + exact D1 counters; IPs hashed with the `IP_HASH_SECRET` key), body size caps, CORS restricted to the Pages origin(s); localhost on any port is added only by `wrangler dev` (`bun run --cwd workers/api dev`, port 18686). D1 migrations already applied remotely are pinned in `workers/api/migrations.lock.json` (tests fail on an edit). DTOs live in `packages/shared/src/api.ts`; co-op messages in `packages/shared/src/coop.ts` (host-authoritative: guests send inputs 20 Hz, host broadcasts quantized snapshots 15 Hz, events reliable, card picks per player).

## 11. Quality gates

- Perf: 1080p desktop dGPU 400 enemies + VFX ≥60 fps; iGPU ≥45; mid Android 250 enemies ≥30 fps. Menu payload < 6 MB, zone < 20 MB (raised from 15 MB on 2026-11-07 by the user; 13 MB stays the soft target; Cloudflare Pages limits only files: 25 MiB each).
- Payload policy (what is fetched when): boot = JS/CSS, manifest, menu art/fonts and the UI sounds only; the first gesture adds the menu music + in-run core sounds (`audio/index.ts`, nothing is audible before it); a run loads before it starts only what the first seconds show: the creatures of its first time band (`enemyUsed`), the ground albedo and the textures its walls, bridges and procedural props sample (`structures/index.neededTextures`: its own zone stone, no normal maps) and its Forge prop GLBs (embedded WebP atlas capped at 1024 px, `PROP_TEX_MAX` in `tools/forge/src/archetypes/prop/texCap.ts`;
